## G03 scope and trace conventions

All rows below use **OSW SHA above**. Paths are relative to `OpenSuperWhisper/`, unless beginning `OpenSuperWhisperTests/`. Source URL: `https://github.com/Starmel/OpenSuperWhisper/blob/c8e6fe79d6851078940f459ab7dbc8ee39e2a97d/OpenSuperWhisper/<path>`; tests omit the extra `OpenSuperWhisper/`. Each path/function was read; test references identify actual assertions, not claimed execution. Native Xcode/macOS suites cannot run on Windows (`command -v xcodebuild` finds no executable).

Disposition: **PORT** = reuse proven technique after Windows validation; **PRESERVE** = preserve product contract; **GAP** = required Desktop Pet capability absent/insufficient upstream; **OUT_OF_SCOPE** = mapped but not needed for three flows; **UNVERIFIED** = further candidate investigation needed. These are design inputs, not implementation PASS.

## Windows adaptation and scope conclusions (G03 only)

1. OSW validates the **stop → local final → intentional paste** workflow and mature ownership/latency techniques. It does not satisfy genuine live text, intended-target/caret verification, Windows integrity/secure-field safety or measured VI accuracy. Those remain mandatory Desktop Pet gates; no acceptance reduction.
2. Exact OSW short-tap toggle and double-Esc defaults differ from SPEC's separate hold short-press discard/immediate Esc. Preserve the explicit approved Windows contract; do not silently advertise identical trigger semantics.
3. Borrow resident model/fresh per-record decode, serial capture, tail/resampler preservation, cancellation identity fences, nonactivation/bounded geometry and clipboard ownership guard. Concrete owners remain existing Go UI/controller and Python audio/inference; **G05** determines narrow implementation files after G04 evidence.
4. Full media-import library, Hebrew model catalog, macOS modifier/mouse onboarding keyboard illustration, alternative platform engines, cloud providers, agent framework and GPU orchestration are **OUT_OF_SCOPE** for this goal unless a failing locked gate justifies them.
5. Stronger target/clipboard/lifetime safety must be Windows tested, not copied as a claim from OSW. No source-parity row passes G06–G14.

## G04 preliminary findings and next work (not accepted)

- Handy installed release rejects hidden `--transcribe-worker --cpu-only` (exit2, unknown argument); source default branch exposes it, **release v0.9.8 does not**. Candidate worker probe exited cleanly; no resident internal integration works in installed binary. Prefer supported APIs or proven engine reuse with explicit pinned distribution, not unsupported CLI assumptions. Release SHA is separately fetched.
- Handy streaming-capable Nemotron CPU batch faster than Whisper Medium in one synthetic sample but wrong final word; not VI accuracy superiority. Need offline GUI toggle/hold/cancel/partial/paste and capture/source review before deciding external integration.
- Handy default-branch `paste_tx/windows.rs` receipt mechanism is debug/settings-gated, not automatically mature released behavior; receipt cannot prove target identity, snapshot skips some formats, restore race must be addressed. `paste_tx/mod.rs` uses200ms quiet/8s timeout, tests source-read only.
- OpenWhispr Windows helper explicitly falls through to current foreground when target restore fails. **Reject this behavior for A04**, not an acceptable convenience fallback. Broader JS/local streaming mapping pending.
- Existing caption donor 27 tests pass but actual-code probes show stale stable prefix and one-character false overlap corruption (BENCHMARK.md). Reuse only verified techniques, not the flawed stabilizer/stitcher wholesale.
- Finish G04 source/actual Windows experiments, then G05 architecture decision. G06/G13 remain real runtime proof, not extrapolated from preliminary batch timings.
